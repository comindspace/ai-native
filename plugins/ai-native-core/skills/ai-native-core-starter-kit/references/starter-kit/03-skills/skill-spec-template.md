# Skill Spec Template

## 1. Skill overview

- `Skill name`
- `Owner`
- `Primary role`
- `Status`
- `Decision mode`

## 2. Business purpose

Какую конкретную работу должен выполнять skill и какой эффект это должно дать бизнесу.

## 3. Trigger

- когда запускается skill;
- кто его запускает;
- какой сигнал или событие считается валидным стартом.

## 4. Inputs

- обязательные входы;
- необязательные входы;
- минимальный набор для запуска;
- качество и источник входных данных.

## 5. Processing logic

Опиши шаги без привязки к конкретной платформе:

1. Получить вход.
2. Проверить полноту и валидность.
3. Получить данные из утверждённых источников.
4. Сформировать результат.
5. Проверить ограничения.
6. Передать в `Delegate`, `Review` или `Own` режим.

## 6. Outputs

- формат результата;
- обязательные поля;
- критерии useful output;
- что считается неуспешным завершением.

## 7. Systems and tools

- какие системы читает;
- какие системы может обновлять;
- какие действия требуют approval;
- какие действия запрещены.

## 8. Source of truth

- на какие системы опирается skill;
- что делать при конфликте данных;
- какие неофициальные источники запрещены.

## 9. Risks and failure modes

- недостающие данные;
- противоречивые данные;
- ошибочная классификация;
- unsafe action;
- ложная уверенность в ответе.

## 10. Review and escalation

- кто reviewer;
- что именно он проверяет;
- при каких условиях skill должен остановиться;
- кому и как эскалировать кейс.

## 11. Quality criteria

- полнота;
- точность;
- соответствие формату;
- прозрачность источников;
- отсутствие policy violations.

## 12. Evaluation plan

- какие тестовые кейсы нужны;
- какие метрики качества будем смотреть;
- какой порог считаем достаточным для пилота;
- какой business metric должен измениться.

## 13. Release readiness

- owner назначен;
- SoT подтверждён;
- pilot scope понятен;
- reviewer назначен;
- eval plan есть;
- rollback path понятен.
