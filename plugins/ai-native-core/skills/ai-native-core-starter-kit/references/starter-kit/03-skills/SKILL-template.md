# SKILL Template

## 1. Identity

- `Skill name`
- `Business domain`
- `Owner`
- `Primary role`
- `Status`: draft / test / prod / scale

## 2. Purpose

Что именно должен делать skill и какую бизнес-задачу он закрывает.

## 3. Scope

Что входит:

- типовые сценарии;
- допустимые входы;
- ожидаемые выходы;
- доступные системы;
- ограничения исполнения.

Что не входит:

- соседние сценарии;
- решения вне зоны компетенции;
- действия без явного approval.

## 4. Inputs

- обязательные данные;
- желательные данные;
- источник данных;
- минимальные требования к качеству входа.

## 5. Outputs

- формат результата;
- критерии завершения;
- что считается полезным выходом;
- когда нужен escalation.

## 6. Decision mode

- `Delegate`
- `Review`
- `Own`

Зафиксировать:

- кто reviewer;
- кто финальный owner;
- какие действия запрещены без подтверждения.

## 7. Dependencies

- системы;
- источники истины;
- связанные роли;
- связанные skills;
- необходимые доступы.

## 8. Quality criteria

- полнота;
- точность;
- прозрачность источников;
- форматность выхода;
- отсутствие запрещённых действий.

## 9. Failure modes

- каких ошибок боимся;
- что делать при нехватке данных;
- где обязательна остановка;
- как выглядит безопасный отказ.

## 10. Release readiness

- сценарий описан;
- owner назначен;
- SoT подтверждён;
- тестовые кейсы есть;
- pilot metric определён;
- reviewer назначен.
