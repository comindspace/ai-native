# Integration Patterns

## Принцип

`AI-Native Core` не должен зависеть от хаотичных ad hoc подключений к системам. Нужны повторяемые паттерны интеграции.

## 1. Read-only pattern

Используется, когда ассистент:

- читает данные;
- строит summaries;
- проверяет статусы;
- формирует рекомендации;
- не меняет system of record.

Подходит для:

- CRM reads;
- ERP reads;
- task/status reads;
- knowledge base queries;
- выгрузок и approved views.

Плюсы:

- минимальный риск;
- быстрый старт;
- хороший режим для первой волны.

## 2. Write-with-review pattern

Используется, когда ассистент готовит изменение, но человек его утверждает.

Подходит для:

- draft updates in systems;
- создание задач;
- подготовка писем;
- обновление карточек;
- предложения изменений в knowledge base.

Требования:

- есть reviewer;
- понятен approval path;
- логируется proposed vs approved action.

## 3. Write-with-approval pattern

Используется, когда действие влияет на системные данные и требует явного подтверждения.

Подходит для:

- изменение статусов;
- запись в операционные системы;
- изменение приоритетов;
- запуск внешних действий.

Требования:

- явный approval checkpoint;
- owner подтверждает действие;
- rollback path понятен.

## 4. Guarded action pattern

Используется для потенциально чувствительных операций.

Требования:

- строгий scope;
- allowlist систем и действий;
- детальный audit trail;
- явный запрет на fallback “сам решу”.

## 5. Pattern selection rule

Новая интеграция по умолчанию стартует как `read-only`.

Переход выше возможен только если:

- доказана польза;
- понятен owner;
- понятен risk profile;
- есть review or approval model.
