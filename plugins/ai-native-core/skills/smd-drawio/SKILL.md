# СМД-схематизация в draw.io

Скилл для работы со схемами по мотивам Системо-Мыследеятельностной методологии (СМД) Г.П. Щедровицкого и ММК в формате draw.io.

## Контекст

- **Методология:** СМД — мета-методология с открытым набором визуальных элементов
- **Формат выхода:** `.drawio` XML (совместим с draw.io Desktop, diagrams.net, Confluence draw.io plugin)
- **Философия и принципы:** `references/smd-rules.md`
- **Стили элементов:** `references/drawio-styles.md`
- **Каталог базовых схем:** `references/base-schemas.md`

> СМД — не фиксированная нотация (как BPMN или UML), а мета-методология. Каждая схема конструируется под ситуацию, но опирается на базовые принципы и каталог устоявшихся паттернов. За каждым словом может стоять схема. Слово без схемы = "узнавание", со схемой = "понимание". Схема — **экзоскелет для ума**: она усиливает мышление, позволяя оперировать структурами, слишком сложными для удержания "в голове".

## Когда использовать

- Пользователь просит: "нарисуй схему", "схематизируй", "покажи схему ситуации"
- Пользователь просит: "распредмети позицию", "из чего состоит деятельность X"
- Пользователь просит: "покажи систему разделения труда", "кто что делает и кому передаёт"
- Пользователь просит: "покажи как перейти от X к Y", "шаг развития", "велосипед"
- Пользователь просит: "выход в рефлексию", "посмотри на ситуацию сверху"
- Пользователь просит: "позиционная коммуникация", "как позиции видят ситуацию"
- Пользователь просит: "какие схемы стоят за этим фреймворком/текстом/концепцией"
- Пользователь просит: "проверь/улучши схему" (для .drawio файла в стиле СМД)

## Разрешённые инструменты

- **Read** — чтение .drawio файлов и references
- **Write** — создание/обновление .drawio файлов
- **Grep/Glob** — поиск .drawio файлов в проекте
- **WebFetch** — загрузка текстов фреймворков/методологий по URL (для команды "Извлечь схемы")

## Команды

### 1. Генерация СМД-схемы

**Как вызвать:**
```
Нарисуй схему: [описание ситуации или название базовой схемы]
Позиции: [список позиций с описанием]
Сохранить в: [путь к файлу.drawio]
```

**Что делаю:**

1. **Прочитать references:**
   - Прочитать `references/smd-rules.md` — все правила и принципы
   - Прочитать `references/drawio-styles.md` — все стили и XML-шаблоны
   - Прочитать `references/base-schemas.md` — каталог базовых схем

2. **Определить тип схемы:**
   - Если запрос на базовую схему (акт деятельности, СРТ, велосипед и т.д.) → взять шаблон из base-schemas.md
   - Если описание ситуации → выбрать подходящую комбинацию базовых схем и примитивов
   - Если непонятно какой тип — спросить: "Что именно вы хотите показать? Кто действует, что делает, с какой проблемой сталкивается?"

3. **Разобрать описание:**
   - Выделить позиции (кто действует — функциональные места)
   - Выделить объекты (материалы, результаты, ситуации)
   - Выделить связи (кто с кем взаимодействует, что передаётся)
   - Определить уровни (есть ли рефлексия? управление? развитие?)

4. **Заполнить шаблон конкретными данными:**
   - Для каждой позиции — конкретные цели, инструменты, материал, результат
   - Для каждой связи — подпись (что передаётся?)
   - Для ситуаций — конкретные названия

5. **Спланировать layout:**
   - Определить размер диаграммы (pageWidth/pageHeight)
   - Разместить элементы с учётом минимизации пересечений стрелок
   - Отступы ≥20px между элементами
   - Рефлексивные позиции — выше обычных
   - Экраны/доски — рядом с рефлексивными позициями

6. **Сгенерировать draw.io XML:**
   - Использовать точные стили из `references/drawio-styles.md`
   - Все ID уникальные (формат: `pos_1`, `goal_1`, `sit_1`, `mat_1`, `res_1`, `edge_1`, ...)
   - Контейнеры и группировки — ПЕРВЫМИ в XML (задний план)
   - Стрелки — ПОСЛЕДНИМИ
   - Шрифт Verdana для всех надписей
   - `pageWidth`/`pageHeight` подобрать под размер диаграммы

7. **Сохранить файл** по указанному пути

**Пример входа:**
```
Нарисуй схему ситуации: CTO и менеджер проекта работают над созданием НМА.
Менеджер передаёт запрос CTO. CTO выходит в рефлексию, анализирует
исходный код на экране (GitHub, AI-ассистент), и создаёт НМА.
Позиции: CTO (рефлексивная), Менеджер проекта
Сохранить в: /path/to/nma.drawio
```

### 2. Распредмечивание позиции

**Как вызвать:**
```
Распредмети позицию: [название позиции]
Контекст: [описание деятельности]
Сохранить в: [путь]
```

**Что делаю:**

1. **Прочитать references** (smd-rules.md, drawio-styles.md, base-schemas.md)

2. **Проанализировать позицию:**
   - Какие **цели** преследует эта позиция? (целеполагание)
   - Какими **знаниями и инструментами** владеет? (средства)
   - С каким **материалом** работает? (вход)
   - Какой **результат** производит? (выход)
   - С какими другими позициями взаимодействует? (кооперация)

3. **Создать схему акта деятельности:**
   - Позиция (центр) — с конкретным названием
   - Целеполагание (справа) — конкретные цели/задачи
   - Знания и инструменты (слева) — конкретные средства
   - Материал (нижний левый) — конкретный вход
   - Результат (нижний правый) — конкретный продукт

4. **При необходимости — расширить до СРТ:**
   - Если взаимодействует с другими позициями — показать связи
   - Чей результат становится чьим материалом?

5. **Сгенерировать draw.io XML** — используя стили из references

6. **Сохранить файл**

**Пример входа:**
```
Распредмети позицию: Технический директор (CTO)
Контекст: AI-консалтинговая компания, создающая решения на LLM для
корпоративных клиентов
Сохранить в: /path/to/cto_position.drawio
```

### 3. Извлечение схем из текста/фреймворка

**Как вызвать:**
```
Извлеки схемы из: [название фреймворка / текст / URL]
Сохранить в: [путь]
```

**Что делаю:**

1. **Прочитать references** (smd-rules.md для принципов анализа)

2. **Прочитать/загрузить исходный текст:**
   - Если указан URL — загрузить через WebFetch
   - Если указано название фреймворка — использовать свои знания
   - Если указан путь к файлу — прочитать файл

3. **Идентифицировать скрытые схемы:**
   - Какие **позиции** подразумеваются? (кто действует?)
   - Какие **объекты** и **отношения** между ними?
   - Есть ли **процессная** составляющая? (последовательность шагов)
   - Есть ли **иерархия** или **вложенность**?
   - Есть ли **конфликт позиций** или **позиционная растяжка**?
   - Какие **базовые СМД-схемы** просматриваются? (акт деятельности, СРТ, велосипед, рефлексия, коммуникация)

4. **Эпистемическая разметка** (рекомендуется при извлечении):
   - **[CORE]** — ядро авторской мысли, воспроизведено точно
   - **[EXT]** — экстраполяция из авторских утверждений (явно не сказано, но следует)
   - **[AI-ANALOGY]** — аналогия, проведённая при анализе (может быть неточной)
   - **[AI-HYPOTHESIS]** — гипотеза, требующая проверки

   Разметку указывать в комментариях к схемам, чтобы пользователь видел степень достоверности каждого элемента.

5. **Для каждой выявленной схемы:**
   - Назвать её и описать словами
   - Выбрать подходящий визуальный формат из базовых СМД-схем или комбинации примитивов
   - Сгенерировать draw.io XML

6. **Прокомментировать:**
   - Какие схемы были обнаружены
   - Как они связаны друг с другом
   - Есть ли белые пятна (то, что автор не раскрыл)

**Пример входа:**
```
Извлеки схемы из: Принцип Минто (The Minto Pyramid Principle)
Сохранить в: /path/to/minto_schemas.drawio
```

### 4. Валидация и рефакторинг СМД-схемы

**Как вызвать:**
```
Проверь/улучши схему: [путь к файлу.drawio]
Что сделать: [описание или "общая проверка"]
```

**Что делаю:**

1. **Прочитать references:**
   - `references/smd-rules.md` — правила и принципы
   - `references/drawio-styles.md` — эталонные стили

2. **Прочитать .drawio файл** и разобрать XML

3. **Проверить:**
   - [ ] Все позиции оформлены единообразно (круг + треугольник + подпись)
   - [ ] Рефлексивные позиции отмечены звёздочкой (*)
   - [ ] Целеполагание — мишень (два концентрических круга + перекрестие)
   - [ ] Пунктирные стрелки для мета-переходов/рефлексии
   - [ ] Сплошные стрелки для деятельности/потоков
   - [ ] Не более 3 типов стрелок на схеме
   - [ ] Шрифт Verdana у всех надписей
   - [ ] Отступы ≥20px между элементами
   - [ ] Минимум пересечений стрелок
   - [ ] Минимум изломов стрелок
   - [ ] Чёрно-белое оформление (цвет только с семантическим обоснованием)
   - [ ] Есть заголовок схемы
   - [ ] Каждый элемент имеет подпись

4. **Если рефакторинг:**
   - Применить исправления
   - Стандартизировать стили (привести к эталонным из drawio-styles.md)
   - Улучшить layout (минимизировать пересечения)
   - Если пользователь указал конкретные изменения — применить их
   - Сохранить обновлённый файл

5. **Выдать результат:**
   - Ошибки (нарушения правил) — с указанием элемента и правила
   - Предупреждения (стилистические рекомендации)
   - Что было изменено (если рефакторинг)
   - Если всё в порядке — "Схема валидна"

## Ключевые правила (краткая справка)

> Полные правила — в `references/smd-rules.md`

### Визуальные примитивы
1. **Позиция** — человечек (круг + треугольник + подпись). НЕ конкретный человек, а функциональное место в деятельности
2. **Рефлексивная позиция** — со звёздочкой (*), позиция "над" текущей деятельностью
3. **Целеполагание** — мишень (два концентрических круга с перекрестием)
4. **Ситуация** — горизонтальный эллипс
5. **Экран/Доска** — параллелограмм; `#` внутри = нераспредмеченная схема
6. **Материал/Результат** — прямоугольники
7. **Облачко** — индивидуальное "думание"
8. **Проблема** — две параллельные вертикальные линии (||)

### Базовые схемы
9. **Акт деятельности:** Позиция + Знания/Инструменты + Целеполагание + Материал→Результат
10. **СРТ:** Результат₁ → Материал₂ (кооперация позиций)
11. **Велосипед:** As Is (Позиция + Ситуация) ↔ To Be (Позиция' + Ситуация')
12. **Рефлексивный выход:** изогнутая пунктирная стрелка от позиции к рефлексивной позиции

### Принципы
13. **Двойное прочтение:** каждая схема читается "что есть" И "как делать"
14. **Сплошные линии** = деятельность/потоки; **пунктирные** = мета-переходы/рефлексия
15. **Не более 3 типов стрелок** на одной схеме
16. **Чёрно-белое** по умолчанию; цвет только с семантическим обоснованием
17. **Шрифт Verdana**, отступы ≥20px, минимум пересечений

### Мета-принципы
18. Схема может быть **шаблоном** или **конкретным описанием** — одно заполняется другим
19. За каждым словом может стоять схема. Слово без схемы = "узнавание", со схемой = "понимание"
20. Любая методология, фреймворк, бизнес-книга **содержит в основе набор схем** — умение их видеть есть ключевой навык СМД

## Телеметрия

Считай содержательным запуском случай, когда этот skill выбран для выполнения задачи, а не только открыт как справка.

- Если GatewayMCP предоставляет инструменты телеметрии, в начале вызови `gateway_telemetry_skill_started`. Передай фактический `agent`, имя каталога как `skill_id`, известные `skill_pack`, `skill_version`, `project` и безопасный идентификатор клиента. Неизвестные значения оставь пустыми.
- Сохрани `correlation_id` из ответа. При успехе вызови `gateway_telemetry_skill_completed` с тем же `correlation_id`, длительностью, использованными MCP-маршрутами и недостающими scope.
- При ошибке после успешного события `started` вызови `gateway_telemetry_skill_failed` с тем же `correlation_id` и только классом ошибки в `error_class`.
- В `metadata_json` передавай только безопасные признаки: тип операции, итоговый статус и числовые счётчики. Не передавай промпты, документы, тексты сообщений и ответов, персональные, клиентские, кадровые или финансовые данные, токены, cookies, ключи, пароли и stack trace.
- Недоступность телеметрии не должна блокировать основную работу. Не повторяй неуспешную телеметрическую запись больше одного раза.
