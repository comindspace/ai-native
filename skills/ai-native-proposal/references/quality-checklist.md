# AI-Native Proposal Quality Checklist

Используй перед финальным ответом или документом.

## Позиционирование

- Предложение решает бизнес-задачу, а не продаёт "бота".
- Понятно, где у клиента деньги, риск, скорость, качество или управляемость.
- Есть формулировка AI-Native operating model.
- Язык привязан к отрасли клиента.

## Данные И Source Of Truth

- Названы официальные источники данных.
- Отделены подтверждённые факты от предположений.
- Есть план, что делать с разрозненными документами, чатами, таблицами, CRM, кодом или базами.
- Указано, где нужна история изменений, provenance и audit trail.

## Архитектура

- Есть слой источников.
- Есть data/source-of-truth слой.
- Есть gateway/integration слой.
- Есть deterministic services/rules/analytics слой.
- Есть agent/skills слой.
- Есть UX/review/reporting слой.
- Есть observability, security и governance.

## AI И Автономия

- Не всё названо AI: правила, расчёты и pipelines отделены от LLM.
- Для рискованных действий указан human review.
- Критичные решения не делегированы AI без проверки.
- Есть quality gates и критерии готовности результата.

## First Wave

- Первая волна не слишком широкая.
- Каждый сценарий имеет владельца и метрику.
- Есть эффект за 4-8 недель.
- Есть baseline или список данных для baseline.

## Коммерческая Полезность

- Понятно, почему coMind нужен как AI-Native партнёр.
- Существующие наработки клиента не обесценены.
- Риски названы спокойно и профессионально.
- Следующий шаг конкретный: discovery, workshop, audit, pilot design или КП.

## Красные Флаги

Переписать, если в документе есть:

- "внедрим искусственный интеллект" без процесса и роли;
- "AI будет сам принимать решения" в high-risk домене;
- ROI без baseline;
- архитектура без source of truth;
- "универсальный ассистент для всего";
- много LLM-жаргона и мало языка бизнеса клиента;
- нет вопросов для discovery.
