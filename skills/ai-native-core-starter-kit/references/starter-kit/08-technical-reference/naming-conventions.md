# Naming Conventions

## Зачем

Единый нейминг нужен, чтобы Starter Kit масштабировался без путаницы в ролях, skills, сценариях и артефактах.

## 0. Дата-префикс для рабочих артефактов (операционный дефолт)

Рабочие и датируемые артефакты по умолчанию именуются с префиксом даты создания в формате `YYYY-MM-DD ` (дата, пробел, смысловое название).

Применяется к: черновикам, заметкам, конспектам, выпискам и разборам со встреч, протоколам, рабочим версиям КП и документов, промежуточным выгрузкам.

Примеры:

- `2026-07-30 Методология B2B-переговоров.md`
- `2026-07-23 Постановка задачи Ромашка.txt`
- `2026-07-30 Обсуждение содержательного предложения.docx`

Исключения сохраняют семантические имена без даты: канонические файлы скиллов (`SKILL.md`, `skill.yaml`, `plugin.yaml`), шаблоны, скрипты, конфиги, исходники кода. Для них работают разделы 1–6 ниже.

Правило распространяет на файлы тот же принцип, что уже принят для пресейл-папок (`2026-06-29 Ромашка`, `2026-05 Василёк`). Цель — хронологическая сортируемость и однозначная связь файла с моментом работы.

## 1. Roles

Формат:

`<function>-<role>`

Примеры:

- `commercial-account-manager`
- `delivery-project-manager`
- `operations-coordinator`

## 2. Skills

Формат:

`<domain>-<job-to-be-done>`

Примеры:

- `commercial-lead-qualification`
- `delivery-status-summary`
- `operations-intake-routing`

## 3. Scenarios

Формат:

`<business-unit>-<workflow>-<stage>`

Примеры:

- `sales-opportunity-intake`
- `delivery-weekly-review`
- `operations-request-triage`

## 4. Documents

Формат:

`<artifact>-<scope>.md`

Примеры:

- `pilot-brief-sales.md`
- `source-of-truth-delivery.md`
- `exec-review-wave-1.md`

## 5. Metrics assets

Формат:

`<metric-pack>-<period>`

Примеры:

- `baseline-wave-1`
- `before-after-pilot-01`
- `weekly-review-2026-04-22`

## 6. Rule of clarity

Название должно сразу отвечать на три вопроса:

- к какой функции это относится;
- какую работу описывает;
- на каком уровне находится артефакт.

Если название требует устного объяснения, оно слишком слабое.
