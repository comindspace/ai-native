# Release Gates

## Назначение

Любой новый skill или сценарий проходит единый путь:

`idea -> draft -> test -> pilot -> prod -> scale`

## Gate 1. Idea -> Draft

Требования:

- понятна бизнес-проблема;
- есть process owner;
- описан ожидаемый эффект;
- выбран режим `Delegate / Review / Own`;
- понятен предполагаемый source of truth.

## Gate 2. Draft -> Test

Требования:

- есть skill spec;
- известны входы и выходы;
- известны ограничения;
- назначен reviewer;
- описаны failure modes;
- есть тестовые сценарии.

## Gate 3. Test -> Pilot

Требования:

- сценарий стабильно проходит тестовые кейсы;
- понятны допуски по ошибкам;
- снят baseline;
- выбран pilot scope;
- есть pilot scorecard;
- команда знает, как эскалировать проблемы.

## Gate 4. Pilot -> Prod

Требования:

- пилот дал полезный результат;
- риски поняты;
- найден owner production-режима;
- подтверждён SoT;
- есть rollback logic;
- есть решение, кто и как мониторит качество.

## Gate 5. Prod -> Scale

Требования:

- сценарий устойчив;
- есть измеримый бизнес-эффект;
- нагрузка и поддержка понятны;
- есть candidate teams / functions для расширения;
- стандарты можно переносить без ручной пересборки.

## Правило

Если хотя бы один gate не пройден осознанно, сценарий остаётся в предыдущем статусе. Переход “на доверии” запрещён.
