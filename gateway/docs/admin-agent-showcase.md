# Метрики использования AI

Раздел показывает, как сотрудники и автономные агенты используют AI через
GatewayMCP. Главная страница `/admin` содержит общий обзор метрик с экономикой
договоров и продажами. Использование AI доступно из раздела «Метрики» и общего обзора.

## Страницы

| Страница | Что можно узнать или сделать |
| --- | --- |
| `/admin/showcase` | Посмотреть активность команды, востребованные навыки и автономных агентов |
| `/admin/people` | Найти сотрудника по логину или почте и увидеть его набор клиентов |
| `/admin/people/detail?subject=…` | Посмотреть запуски, исходы, длительность и использование моделей сотрудником |
| `/my/skills` | Посмотреть свою статистику и выбрать любимые навыки |
| `/admin/agents` | Посмотреть каталог автономных агентов и добавить профиль |
| `/admin/agents/detail?key=…` | Настроить источник агента и посмотреть его метрики |

Просмотр чужих метрик и настройка профилей требуют действующих прав
администратора. Право проверяется по текущей политике при каждом запросе.
Личная страница доступна любому авторизованному сотруднику. Изменять избранное
может только его владелец. Формы защищены CSRF, страницы не кешируются.

## Как считаются показатели

- Период равен последним 7, 30 или 90 дням. График группирует события по московскому
  времени. Первый календарный день может быть неполным.
- Запуск определяется событием `started`. Исход берётся из последнего события
  `completed` или `failed` с теми же `actor_subject` и `correlation_id`, полученного
  после начала запуска. Завершения старых запусков в показатели периода не входят.
- Отсутствие исхода означает, что завершение ещё не зарегистрировано. Такой запуск
  может продолжаться или остаться без телеметрии. Статус присутствия не выводится.
- Медианная длительность использует переданные неотрицательные `duration_ms`.
  Рядом указано число завершённых запусков с заполненной длительностью.
- Количество пользователей определяется по учётным записям шлюза. Каталог
  включает сотрудников без запусков. Это не полный кадровый список Yonote.
- Частые навыки определяются по запускам. Избранное хранится отдельно в
  `assistant_skill_favorites` и сохраняется при смене периода. Профиль показывает
  до 12 самых частых навыков и всё избранное с фактическими счётчиками.
- Использование моделей группируется по источнику, качеству измерения и классу
  использования. Данные биллинга и локальные оценки не суммируются между собой.
  Для токенов и стоимости указана заполненность полей. Отсутствующая сумма
  отображается как неизвестная. Заполненная частичная сумма остаётся частичной.

Завершение навыка сообщает сам агент. Эти показатели описывают использование
инструментов. Для оценки качества результата, принятой работы и экономического
эффекта нужны отдельные подтверждения. Экономика договоров остаётся в
общем обзоре метрик и разделе «Экономика».

## Автономные агенты

Профиль хранится в `assistant_agent_profiles`. Администратор явно связывает его
с парой `actor_subject` и `agent` из телеметрии. Для автономного агента нужен
отдельный источник. Hermes в личной сессии сотрудника сам по себе не делает
её автономной.

Один источник может принадлежать только одному профилю. Его запуски исключаются
из личной статистики и относятся к автономному агенту. Общие показатели использования AI
включают их один раз. Текущая привязка применяется ко всему выбранному периоду,
поэтому её изменение пересчитывает отображаемую историю. Номер редакции
защищает от перезаписи чужого изменения из старой формы.

Миграция создаёт профиль Фёклы без привязки. Пока источник не выбран, показатели
и состояние неизвестны. События общего сервиса уведомлений не приписываются
Фёкле. Для количества отправленных сообщений и других действий вне навыков
нужно подключить отдельную телеметрию результатов.

## Ввод в эксплуатацию

Изменение использует добавочную миграцию `0021_agent_showcase.sql`. Перед запуском
нового приложения применяется штатная команда `gateway-mcp migrate up`.
В этом изменении миграция на рабочей базе не запускается. Профили и предпочтения
не меняют права сотрудников или доступ к корпоративным системам.

Для отката интерфейса можно вернуть предыдущий образ приложения, оставив новые
таблицы. Они не изменяют существующие таблицы телеметрии. Удалять предпочтения
и профили при откате не требуется.

## Проверка

Автоматические тесты проверяют авторизацию, личную область данных, CSRF,
неверные и повторяющиеся поля, точную привязку агента, обработку ошибок,
экранирование текста, пропуски в метриках и различие избранного и частоты.
SQL проверяется на синтетических запусках, включая совпадающие идентификаторы
у разных сотрудников, запуски вне периода, отсутствие исходов и неполные затраты.
Макеты с заполненными и пустыми данными проверяются на ширинах 320, 375, 414,
768 и 1440 пикселей. Изображения для проверки используют вымышленные данные.
